# Hosting infrastructure and runtimes for agent marketplaces

**Research date:** 2026-08-08  
**Scope:** A selective, evidence-backed infrastructure map for marketplaces that bundle deployment of agent skills, automations, and MCP servers. It is **not an internet-wide completeness claim**. Prices are public list-price signals observed on the cited pages on the research date, generally before tax, model/API usage, bandwidth, storage, and support. Where an official page was dynamic, unavailable, or did not expose a numeric price, this report says **UNVERIFIED** rather than guessing.

## How to read this catalog

- **Provenance:** **OFFICIAL pricing page** means the cited first-party page exposed the billing model and/or price; **OFFICIAL docs** means first-party documentation supports the product/capability statement but may not publish price; **UNVERIFIED** means the price or current hosted-service claim could not be confirmed from retrievable first-party content. No review-derived prices are used.
- **Cold start:** `edge/very low` (typically milliseconds), `low` (warm container/function), `medium` (container boot/scale-from-zero), `high` (GPU/model load or new VM/browser). These are qualitative architecture classes, not measured SLAs.
- **Capability shorthand:** `P` persistent storage; `C` cron/scheduling; `W` inbound webhooks/HTTP; `S` secrets/OAuth facilities; `X` subprocess/full-container execution; `B` managed browser. `—` means not native or not established by the cited source.

# Synthesis for a one-click agent-skill marketplace

## The de-facto “standard stack” in 2026

There is no single standard, but the lowest-friction pattern is converging on four layers:

1. **Marketplace/control plane:** Next.js/TypeScript on **Vercel** (or Cloudflare) for catalog, checkout, tenant UI, API routes and deployment buttons.
2. **Seller workload plane:** a normalized Git/Docker template deployed to **Railway**, **Render**, **Cloud Run**, or **Fly Machines**. A container contract is more portable than a Vercel-only function contract and supports Python, queues, subprocesses and long-running MCP transports.
3. **Automation plane:** **n8n Cloud** or a marketplace-operated, isolated n8n deployment for schedules, OAuth connectors, webhooks and human-readable workflow editing. LangGraph Deployments is the stronger code-first choice for durable/stateful agent graphs.
4. **Specialized execution:** **Cloudflare Workers** for cheap remote MCP/edge auth; **Browserbase** (or Cloudflare Browser Run) for browsers; **E2B/Daytona** for untrusted code; **Modal/RunPod/Beam** only when a skill actually needs GPU compute. A registry such as Smithery is a distribution channel, not the primary security boundary or hosting control plane.

## Which partners give one-click deployment with least friction?

**Best default: Railway.** Its Git/Docker deploy, variables, volumes, databases, cron, arbitrary process support and low $5 minimum make it the most forgiving seller target. It avoids forcing every skill into serverless-duration constraints. Build one marketplace-owned OCI template/spec and provision projects through Railway's API or deployment templates.

**Best frontend and JavaScript template experience: Vercel.** “Deploy with Vercel” is excellent for stateless TypeScript agents and the marketplace UI. Keep durable jobs, browsers and arbitrary Python workers elsewhere.

**Best cheap remote MCP substrate: Cloudflare Workers + Durable Objects.** The $5 paid minimum, global HTTP termination, OAuth patterns, stateful actors and official remote-MCP guidance make it unusually aligned. Its key limitation is no arbitrary native subprocess, so offer it only for Worker-compatible MCP packages.

**Best cloud-neutral container targets: Google Cloud Run and Render.** Cloud Run gives enterprise identity/networking and scale-to-zero; Render is simpler for managed databases, workers and cron. Both are good second deployment adapters after Railway.

**Best workflow SKU: n8n Cloud.** Execution-based billing, native OAuth credentials, schedules and webhooks match marketplace automations better than asking each seller to implement operations. Per-workspace economics may favor a marketplace-managed n8n control plane rather than one Cloud account per cheap purchase.

**Best specialist adapters:** Modal for burst GPU/Python; Browserbase for reliable remote browser sessions; E2B for isolated generated-code execution. Add these as declared capability add-ons (`gpu`, `browser`, `sandbox`) so most sellers do not pay for them.

## Recommended default architecture

- Define a **portable seller manifest**: image/build source, HTTP/MCP entrypoint, required secrets/OAuth scopes, CPU/RAM, persistence, schedule/webhooks, egress policy, and optional `browser/gpu/sandbox` capabilities.
- Deploy the marketplace UI/control plane on **Vercel**; deploy default seller workloads as isolated **Railway containers** with a Render/Cloud Run adapter next.
- Route Worker-compatible remote MCP servers to **Cloudflare Workers + Durable Objects**.
- Represent no-code automations as versioned **n8n workflow JSON**, with credentials bound by the buyer at install time.
- Never run arbitrary seller skills in the marketplace web process. Use per-tenant containers/microVMs and **E2B/Daytona/Fly Machines** for untrusted code; use least-privilege secrets, outbound-network policy, quotas, signed artifacts and auditable deployment logs.
- Negotiate reseller/API/white-label terms before promising “hosting included”: most public self-serve prices describe end-customer usage, not marketplace resale, account delegation, data processing, or margin guarantees.

## Important limitations

- Public prices and plan names change, and several pages are JavaScript-rendered. This snapshot records what was retrievable on **2026-08-08**; dynamic or unclear figures are explicitly marked **UNVERIFIED**.
- “One click” can mean a deploy-button handoff into the buyer's cloud account or true marketplace-managed hosting. The latter carries materially different security, abuse, support, tax, privacy and vendor-resale obligations.
- AutoGen, Stagehand, Playwright, LobeHub, OpenClaw and dstack are runtimes/frameworks or self-host patterns—not turnkey managed hosting. Registry listing likewise does not prove managed execution.
